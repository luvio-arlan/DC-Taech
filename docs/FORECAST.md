# 需求预测教学模块

本模块在原版 NEXUS 的基础上，加入了一个**按需算力市场**：合同之外，市场每天还有新的 GPU 需求。玩家要先预测这部分需求，再决定采购多少设备。游戏内入口是底部工作台的「需求预测」。

本版按课程安排**删除 Holt-Winters**，加入**高斯过程回归（Gaussian Process，GP）**。GP 不只是一条点预测曲线：它给出完整的高斯预测分布，均值用于订货，方差用于区间和安全量。Holt 仍保留，作为“趋势 + 无季节”的对照方法。

## 1. 需求从哪里来

每天的按需需求 Dₜ（单位：GPU，指当天平均同时需要的 GPU 数）由下式生成：

```
Dₜ = round( (160 + 2·(t − 1) + 冲击ₜ) × 季节指数(星期) × (1 + 0.05·εₜ) )
冲击ₜ = 120（t ≥ 15），否则为 0
季节指数（周一到周日）= 1.08, 1.12, 1.12, 1.10, 1.04, 0.80, 0.74
εₜ ~ N(0, 1)，截断在 ±3
```

- 第 1 天是周一。开局前预置 8 周历史（第 −55 天到第 0 天），让 Holt 的静态初始化和 GP 的训练窗口都有足够数据。
- 随机种子固定，**全班看到的数据完全相同**，方便统一讲解和对答案。
- 第 15 天的需求冲击不提前预告，结算当天才会出现市场快讯。学生可以借助跟踪信号和 GP 预测区间来发现它。
- 所有参数都在 `lib/forecast.ts` 的 `MARKET` 对象里。改种子、趋势、冲击日期或幅度，就能生成新的教学情景。

## 2. 经营规则的变化

- 合同优先占用就绪算力；剩余算力按 $3.50 / GPU·h 服务按需需求。
- 满足不了的按需需求直接流失（缺货损失），不罚款，但会损失收入。
- GPU 每批 64 张（8 台八卡服务器，$1.8M），可以一次采购多批。每批数量较小，避免凑整吞掉不同预测方法之间的差别。
- 已安装但没有交付给客户的 GPU 每天记为闲置（GPU·天），与缺货并排显示在看板上。
- 当天的实际需求要点「下一天」结算后才知道。结算前，界面上的“预计日收入”和订货建议使用所选方法的预测值。
- 董事会目标不变。“交付 768 GPU”的统计包含按需市场的交付，按最近一次结算的**实际**需求计算，与所选预测方法无关。

## 3. 六种方法

| 方法 | 公式 | 初始化 / 说明 |
|---|---|---|
| 朴素法 | Fₜ₊₁ = Dₜ | 无参数，作为比较基准 |
| 简单移动平均 SMA | Fₜ₊₁ = (Dₜ + … + Dₜ₋ₙ₊₁) / n | 凑齐 n 期后开始 |
| 加权移动平均 WMA | Fₜ₊₁ = w₁Dₜ + w₂Dₜ₋₁ + …，Σw = 1 | 权重自动归一 |
| 一次指数平滑 SES | Fₜ₊₁ = αDₜ + (1 − α)Fₜ | F₂ = D₁ |
| Holt 双参数 | Lₜ = αDₜ + (1 − α)(Lₜ₋₁ + Tₜ₋₁)；Tₜ = β(Lₜ − Lₜ₋₁) + (1 − β)Tₜ₋₁；Fₜ₊ₕ = Lₜ + hTₜ | 静态法：前 28 期做 7 日中心移动平均去季节，再回归得 L₀、T₀ |
| 高斯过程 GP | 见下节 | 最近 56 天；线性趋势 × 星期因子为均值，GP 拟合残差 |

### 3.1 GP 的模型

GP 把未知函数看作随机函数。任意有限个位置上的函数值服从联合高斯分布：

```
f(x) ~ GP(m(x), k(x, x′))
yₜ = f(xₜ) + εₜ，  εₜ ~ iid N(0, σₙ²)
```

均值函数写成“线性趋势 × 星期因子”：

```
m(x) = (a + b·x) · S_weekday(x)
```

其中 `a、b` 由最近 56 天的普通最小二乘得到；`S` 是各星期“实际值 ÷ 趋势值”的平均，向 1 收缩后归一，使 7 个因子之和为 7。这样处理的原因是需求同时有增长趋势和乘法周季节；直接把原始需求丢给零均值 GP，会把趋势误当成缓慢波动。

核函数默认是 **RBF + 周期核**：

```
k(x, x′) = σ_f² exp(−(x − x′)² / (2ℓ²))
         + σ_p² exp(−2 sin²(π|x − x′| / 7) / ℓ_p²)
```

- RBF 描述平滑的短期相关；周期核描述一周 7 天的重复形态，固定周期 p = 7、周期长度尺度 ℓ_p = 1.5。
- 也可以只选 RBF。两种核共用同一套均值函数，便于比较“是否显式建模周季节”。
- 超参数在界面上可调：ℓ、σ_f²、σ_p²、σ_n²。默认值为 ℓ = 3 天、σ_f² = 600、σ_p² = 300、σ_n² = 50。
- GP 只使用最近 56 天（8 周）的数据拟合；这样既能适应需求水平变化，也把矩阵规模控制在教学可接受的范围内。

### 3.2 GP 的后验预测分布

给定训练点 `X, y`，在新位置 `x*` 处：

```
μ* = m(x*) + k*ᵀ (K + σₙ² I)⁻¹ (y − m)
v* = k** − k*ᵀ (K + σₙ² I)⁻¹ k*
ŷ* ~ N(μ*, v* + σₙ²)
```

- `k*` 是训练点与 `x*` 的核向量，`k** = k(x*, x*)`。
- `v*` 是潜在函数的后验方差；**未来观测**的方差还要加 `σₙ²`。界面中 `σₜ` 列和预测区间用的都是 `v* + σₙ²`。
- 后验方差与观测值无关（固定核和噪声时）；观测增多时，相关区域内的方差通常缩小。
- 游戏里 GP 使用固定 56 天滚动窗口。平稳核下，每一期到“下一期”的相对位置相同，所以逐期计算表中的一步 `σₜ` 基本不变；改变预测步数 h 才会让区间明显变宽。这不是程序把方差写死，而是固定窗口 + 平稳核的数学结果。
- 计算使用 Cholesky 分解 `K + σₙ²I = L Lᵀ`，解线性方程组，不显式求逆。加入极小的数值 jitter 仅用于稳定分解，**不替代** `σₙ²`。

### 3.3 从服务水平到预测区间

订货建议的 `z` 是**单侧服务水平**的分位数（95% → 1.645）。画在需求曲线上的预测区间是对称区间，应使用同一覆盖率的双侧分位数：

```
z_interval = Φ⁻¹((1 + Φ(z)) / 2)
```

例如 95% 服务水平的 `z = 1.645`，对应双侧 95% 区间的 `z_interval = 1.96`。界面里的区间标注和计算都使用这个换算；GP 的 `σ` 来自后验预测分布，其他方法的 `σ` 来自回测的 h 步误差均方根。

## 4. 误差指标与 GP 校准

误差记为 eₜ = Dₜ − Fₜ（实际 − 预测，正数表示预测偏低）。以下指标只统计最近 28 天，保证不同方法在同一窗口下比较：

- MAD = Σ|eₜ| / n
- MSE = Σeₜ² / n，RMSE = √MSE
- MAPE = Σ(|eₜ| / Dₜ) / n × 100%
- 偏差 = Σeₜ / n
- 跟踪信号 TS = Σeₜ / MAD；|TS| > 4 时报警

GP 还给出预测标准差，因此除了点误差，还应看：

- 95% 区间的经验覆盖率是否接近 95%；
- 平均区间宽度是否过大（覆盖率高但区间过宽同样没有决策价值）；
- 需求冲击后覆盖率和宽度怎样变化。

本版 GP 的方差是**固定超参数、给定模型**下的后验方差，不包含超参数估计误差和核误设；所以覆盖率偏低时，不要用“GP 说方差很小”直接下结论，应先检查均值结构、核与噪声假设。课堂上可以把 ℓ 调小、把 σ_n² 调大，观察区间怎样变化。

## 5. 订货建议：产能版的补货到目标水平

GPU 是**产能**，不是消耗品。需求是“每天同时要用多少 GPU”，所以补货目标是一个容量水平，而不是提前期内的累计需求量。这一点和教材里的库存模型不同，可以拿来做课堂讨论。

```
目标就绪容量 S = max（到货时仍有效的合同 GPU + 当天按需需求预测）+ z × σ，max 取交货窗口内的各天
缺口 = S − 现有 − 在途；建议批数 = ⌈缺口 ÷ 每批容量⌉
```

- **交货窗口**：今天下单的 GPU 在第 t + L 天到货（L = 5）。窗口从这一天开始，覆盖检查周期 R 天。
- **σ（GP）**：取交货窗口内各步 GP 预测标准差的**最大值**，包含观测噪声 `σₙ²`。它反映模型内的预测不确定性，不包含核误设和超参数不确定性。
- **σ（其他方法）**：用历史回测得到的 h 步预测误差均方根；回测样本不足时，退回 σ₁·√h 的教材近似。
- **合同**：只计入到货当天仍然有效的合同。到货前就会到期的合同不计入，否则会多买。
- **z**：由目标服务水平决定，可选 90%、95%、97.5%、99%，也可以直接选由成本比推出的临界比。
- 光互联、存储、冷却、电力都折算为“可支持的 GPU 数”，与 GPU 共用同一个目标。电力按每 MW 支持 641 GPU 折算。

## 6. 缺货与闲置：临界比

两类错误的单位成本（每 GPU·天，教学假设，定义在 `lib/game.ts` 的 `COSTS`）：

| | 构成 | 数值 |
|---|---|---|
| 缺货成本 Cᵤ | 流失的按需收入 $3.50 × 24，减去省下的满载与待机电费差 | ≈ $81.5 |
| 闲置成本 Cₒ | 直线折旧（单卡 $28,125 ÷ 5 年）$15.4 + 资金占用（年化 10%）$7.7 + 维护 $1.5 + 待机电费 $0.3 | ≈ $24.9 |

临界比 = Cᵤ ÷ (Cᵤ + Cₒ) ≈ 0.77，对应 z ≈ 0.73。这是报童模型的思路：缺一台比多一台贵，服务水平就应当高于 50%；但并不需要 95%。

GPU 容量是长期资产，每天都在用，所以报童模型在这里只是近似：真正的权衡发生在多期之间。建议课堂用同一服务水平分别跑 GP、Holt 和 SES，比较“缺货 + 闲置”总成本和期末现金，而不是只看 MAD。GP 的区间更“诚实”还是更“保守”，取决于核、噪声和需求冲击后的模型误设。

## 7. 课堂练习建议

1. **趋势下的滞后**：用 SMA（n = 3、7、14）和 SES（α = 0.1、0.3、0.7）预测冲击前的数据。比较偏差和 TS，解释为什么在增长的需求下，它们的预测会系统性偏低。
2. **季节性**：比较 Holt 与 GP 的逐期误差，按星期分组，看周末的误差有什么规律。再切换 GP 的 RBF / RBF + 周期，观察周季节由谁解释。
3. **需求冲击**：推进到第 15 天之后，记录每种方法的 TS 第几天超过 ±4、第几天回到范围内。GP 的预测区间在冲击后是否变宽？覆盖率是否下降？
4. **手算核对**：导出 CSV，在 Excel 中复算一次指数平滑和 Holt 的前 5 期。GP 可以手算下面这个单点例子：
   - `x = [0]`、`y = [1]`、`ℓ = 1`、`σ_f² = 1`、`σ_n² = 0.1`；
   - `x* = 0`：μ* = 0.9091，潜在方差 0.0909，观测方差 0.1909；
   - `x* = 1`：μ* = 0.5514，潜在方差 0.6656，观测方差 0.7656。
   - 核矩阵：`x = (0,1,2)`、`ℓ = 0.5` 时，`k(0,1) = e⁻² = 0.1353`、`k(0,2) = e⁻⁸ = 0.000335`，与授课讲义一致。
5. **超参数**：固定数据，分别把 ℓ 调成 1、3、10，把 σ_n² 调成 10、50、200，记录 MAD 和 95% 区间覆盖率。讨论“误差小”和“区间可用”不是同一件事。
6. **预测到决策**：两组同学用不同方法、相同服务水平经营 30 天，比较看板上的“缺货 vs 闲置”成本和期末现金。
7. **临界比**：同一种方法分别用 95% 和临界比经营，比较总成本；再改 `COSTS` 里的资金成本或折旧年限，看临界比怎样变化。

## 8. 计算校验

GP 的数值实现放在 `lib/forecast.ts`，核心检查包括：

- `rbfKernel`、`gpKernel` 与手算核矩阵逐项对照；
- `gpPosterior` 与授课讲义的单点后验对照（见练习 4 的数值）；
- Cholesky 分解、三角回代与矩阵直接求解的结果对照；
- 观测增加时同一位置的后验方差不增；预测方差由 `v* + σₙ²` 组成且非负；
- GP 的点预测、`sdAhead`、区间分位数和订货建议的 `sigma` 使用同一套后验量；
- 旧存档里的 `hw` 方法会被安全回退到默认方法，不会让页面崩溃。

相关测试在 `tests/forecast.test.ts`。运行 `npm test` 即可复现。

## 9. 代码位置

- `lib/forecast.ts`：需求生成、六种方法、GP 核与后验、误差指标、h 步误差、区间分位数。
- `lib/game.ts`：按需市场结算（`metrics`、`act` 中的 `next`）以及订货建议（`recommendation`）。
- `app/forecast-panel.tsx`：「需求预测」面板（预测看板、逐期计算表、方法对比、订货建议）。
- `app/scene.tsx`：CEO 办公室双屏上方的需求预测屏，实时显示今日预测、误差指标、跟踪信号和未来 7 天预测区间。
- `tests/forecast.test.ts`：与手算结果、授课讲义数值对照的测试。运行 `npm test`。
