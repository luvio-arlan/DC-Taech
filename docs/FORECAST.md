# 需求预测教学模块

本模块在原版 NEXUS 的基础上，加入了一个**按需算力市场**：合同之外，市场每天还有新的 GPU 需求。玩家要先预测这部分需求，再决定采购多少设备。游戏内入口是底部工作台的「需求预测」。

## 1. 需求从哪里来

每天的按需需求 Dₜ（单位：GPU，指当天平均同时需要的 GPU 数）由下式生成：

```
Dₜ = round( (160 + 2·(t − 1) + 冲击ₜ) × 季节指数(星期) × (1 + 0.05·εₜ) )
冲击ₜ = 120（t ≥ 15），否则为 0
季节指数（周一到周日）= 1.08, 1.12, 1.12, 1.10, 1.04, 0.80, 0.74
εₜ ~ N(0, 1)，截断在 ±3
```

- 第 1 天是周一。开局前预置 8 周历史（第 −55 天到第 0 天），这样 Holt-Winters 有足够数据做初始化。
- 随机种子固定，**全班看到的数据完全相同**，方便统一讲解和对答案。
- 第 15 天的需求冲击不提前预告，结算当天才会出现市场快讯。学生可以借助跟踪信号来发现它。
- 所有参数都在 `lib/forecast.ts` 的 `MARKET` 对象里。改种子、趋势、冲击日期或幅度，就能生成新的教学情景。

## 2. 经营规则的变化

- 合同优先占用就绪算力；剩余算力按 $3.50 / GPU·h 服务按需需求。
- 满足不了的按需需求直接流失（缺货损失），不罚款，但会损失收入。
- GPU 每批 64 张（8 台八卡服务器，$1.8M），可以一次采购多批。原版每批 256 张，凑整会吞掉不同预测方法之间的差别。
- 已安装但没有交付给客户的 GPU 每天记为闲置（GPU·天），与缺货并排显示在看板上。
- 当天的实际需求要点「下一天」结算后才知道。结算前，界面上的“预计日收入”使用所选方法的一步预测。
- 董事会目标不变。“交付 768 GPU”的统计包含按需市场的交付，按最近一次结算的**实际**需求计算，与所选预测方法无关。

## 3. 六种方法

| 方法 | 公式 | 初始化 |
|---|---|---|
| 朴素法 | Fₜ₊₁ = Dₜ | 无 |
| 简单移动平均 SMA | Fₜ₊₁ = (Dₜ + … + Dₜ₋ₙ₊₁) / n | 凑齐 n 期后开始 |
| 加权移动平均 WMA | Fₜ₊₁ = w₁Dₜ + w₂Dₜ₋₁ + …，Σw = 1 | 权重不为 1 时自动归一 |
| 一次指数平滑 SES | Fₜ₊₁ = αDₜ + (1 − α)Fₜ | F₂ = D₁ |
| Holt 双参数 | Lₜ = αDₜ + (1 − α)(Lₜ₋₁ + Tₜ₋₁)；Tₜ = β(Lₜ − Lₜ₋₁) + (1 − β)Tₜ₋₁；Fₜ₊ₕ = Lₜ + hTₜ | 静态法：前 28 期做 7 日中心移动平均去季节，再回归得 L₀、T₀ |
| Holt-Winters（乘法季节，m = 7） | Lₜ = α(Dₜ / Sₜ₋ₘ) + (1 − α)(Lₜ₋₁ + Tₜ₋₁)；Tₜ 同上；Sₜ = γ(Dₜ / Lₜ) + (1 − γ)Sₜ₋ₘ；Fₜ₊ₕ = (Lₜ + hTₜ)Sₜ₊ₕ₋ₘ | 静态法：前 28 期去季节后回归得 L₀、T₀；各星期“实际 ÷ 回归值”的平均作为初始季节指数，归一使合计为 7 |

## 4. 误差指标

误差记为 eₜ = Dₜ − Fₜ（实际 − 预测，正数表示预测偏低）。以下指标只统计最近 28 天，保证不同方法在同一窗口下比较：

- MAD = Σ|eₜ| / n
- MSE = Σeₜ² / n，RMSE = √MSE
- MAPE = Σ(|eₜ| / Dₜ) / n × 100%
- 偏差 = Σeₜ / n
- 跟踪信号 TS = Σeₜ / MAD；|TS| > 4 时报警

「逐期计算表」列出每一期的 Dₜ、Fₜ、eₜ、|eₜ|、eₜ²、APE，以及方法的中间量 Lₜ、Tₜ、Sₜ。还可以导出全部历史为 CSV（带 BOM，Excel 直接打开不会乱码），供学生在 Excel 中逐格复算。

## 5. 订货建议：产能版的补货到目标水平

GPU 是**产能**，不是消耗品。需求是“每天同时要用多少 GPU”，所以补货目标是一个容量水平，而不是提前期内的累计需求量。这一点和教材里的库存模型不同，可以拿来做课堂讨论。

```
目标就绪容量 S = max（到货时仍有效的合同 GPU + 当天按需需求预测）+ z × σ，max 取交货窗口内的各天
缺口 = S − 现有 − 在途；建议批数 = ⌈缺口 ÷ 每批容量⌉
```

- **交货窗口**：今天下单的 GPU 在第 t + L 天到货（L = 5）。窗口从这一天开始，覆盖检查周期 R 天。
- **σ**：用历史回测得到的 (L + 1) 步预测误差的均方根。回测样本不足时，退回教材近似 σ₁·√(L + 1)。
- **合同**：只计入到货当天仍然有效的合同。到货前就会到期的合同不计入，否则会多买。
- **z**：由目标服务水平决定，可选 90%、95%、97.5%、99%。
- 光互联、存储、冷却、电力都折算为“可支持的 GPU 数”，与 GPU 共用同一个目标。电力按每 MW 支持 641 GPU 折算。

## 6. 缺货与闲置：临界比

两类错误的单位成本（每 GPU·天，教学假设，定义在 `lib/game.ts` 的 `COSTS`）：

| | 构成 | 数值 |
|---|---|---|
| 缺货成本 Cᵤ | 流失的按需收入 $3.50 × 24，减去省下的满载与待机电费差 | ≈ $81.5 |
| 闲置成本 Cₒ | 直线折旧（单卡 $28,125 ÷ 5 年）$15.4 + 资金占用（年化 10%）$7.7 + 维护 $1.5 + 待机电费 $0.3 | ≈ $24.9 |

临界比 = Cᵤ ÷ (Cᵤ + Cₒ) ≈ 0.77，对应 z ≈ 0.73。这是报童模型的思路：缺一台比多一台贵，服务水平就应当高于 50%；但并不需要 95%。「订货建议」的服务水平里可以直接选“临界比”。

GPU 容量是长期资产，每天都在用，所以报童模型在这里只是近似：真正的权衡发生在多期之间。模拟中（每天严格按建议采购，第 21–40 天）：

- 服务水平从 95% 改为临界比，所有方法的“缺货 + 闲置”总成本都下降，例如 SES 从约 $12.9 万降到约 $10.3 万。
- 误差最小的 Holt-Winters 总成本反而高于 SES：第 15 天需求跳升后，带趋势项的方法把跳升当成持续增长外推，买多了。误差指标好不等于决策成本低，这一点值得课堂讨论。

## 7. 课堂练习建议

1. **趋势下的滞后**：用 SMA（n = 3、7、14）和 SES（α = 0.1、0.3、0.7）预测冲击前的数据。比较偏差和 TS，解释为什么在增长的需求下，它们的预测会系统性偏低。
2. **季节性**：比较 Holt 与 Holt-Winters 的逐期误差，按星期分组，看周末的误差有什么规律。
3. **需求冲击**：推进到第 15 天之后，记录每种方法的 TS 第几天超过 ±4、第几天回到范围内。讨论反应速度与平滑之间的权衡。
4. **手算核对**：导出 CSV，在 Excel 中复算一次指数平滑和 Holt-Winters 的前 5 期，与游戏结果对照。
5. **预测到决策**：两组同学用不同方法、相同服务水平经营 30 天，比较看板上的“缺货 vs 闲置”成本和期末现金。
6. **临界比**：同一种方法分别用 95% 和临界比经营，比较总成本；再改 `COSTS` 里的资金成本或折旧年限，看临界比怎样变化。
7. **趋势外推的风险**：观察第 15 天之后 Holt 与 Holt-Winters 的趋势项 Tₜ，解释为什么它们在需求跳升后会买多。

## 8. 代码位置

- `lib/forecast.ts`：需求生成、六种方法、误差指标、h 步误差。不依赖游戏状态，可以单独使用。
- `lib/game.ts`：按需市场结算（`metrics`、`act` 中的 `next`）以及订货建议（`recommendation`）。
- `app/forecast-panel.tsx`：「需求预测」面板（预测看板、逐期计算表、方法对比、订货建议）。
- `app/scene.tsx`：CEO 办公室双屏上方的需求预测屏，实时显示今日预测、误差指标、跟踪信号和未来 7 天预测区间，点击可打开面板。
- `tests/forecast.test.ts`：与手算结果对照的测试。运行 `npm test`。
